## 1. Executive Summary & Core Principles

PlannedEducation is a modern, privacy-first, open-source teacher's aid, exam-taking environment, and automated grading system. It is designed to provide teachers, schools, and universities with powerful automated grading and classroom analytics without compromising student data privacy or test integrity.

### Dual-Layer Documentation Standard
Every major topic in this manual is presented in two complementary layers:
1. **For Teachers, Students & School Users**: Plain-English explanations, real-world classroom workflows, and step-by-step guidance without technical jargon.
2. **For IT Administrators & Technical Experts**: In-depth architectural details, protocols, cryptographic hashing algorithms, database schemas, HTTP headers, filesystem structures, and code mechanics.

### Core Architectural Guardrails
1. **🚫 Strictly Zero Paid Services — Ever**:
   PlannedEducation NEVER relies on paid cloud databases (AWS RDS, Google Cloud SQL paid tiers), paid authentication providers (Auth0, Clerk, Okta), paid email/SMS services (SendGrid, Twilio), or paid AI subscriptions. All core functions run locally and indefinitely for free on commodity hardware.
2. **🛡️ Student Privacy & FERPA / GDPR Compliance**:
   All student identities, exam submissions, and grades remain strictly inside the school's local database. When AI assistance is used for grading or drafting, **Microsoft Presidio PII anonymization** automatically scrubs names, dates, phone numbers, locations, and email addresses before external transmission.
3. **🔒 Deterministic & Offline-First Core**:
   The core grading engine, exam delivery, randomizer math engines, and SEB validation operate deterministically without requiring continuous internet connectivity. If the school Wi-Fi drops during an exam, student progress is saved locally and synced once connectivity is restored.
4. **🤖 Bring-Your-Own-Key (BYOK) for Optional AI**:
   PlannedEducation contains no forced internal LLMs. Teachers and administrators who choose to utilize AI grading or AI exam drafting can configure their own preferred provider (Ollama for 100% offline local inference, Google Gemini, OpenRouter, Anthropic Claude, Mistral, Groq, or OpenAI) in **Settings > AI Keys**.

## 2. Platform Configuration: Required vs. Optional Settings

PlannedEducation is designed to operate out-of-the-box with minimal configuration while offering enterprise-grade extensibility for complex campus networks.

### Configuration Matrix Overview

| Environment Variable | Status | Default / Fallback | Purpose & Why It Is Required or Optional |
|:---|:---:|:---|:---|
| `JWT_SECRET_KEY` | **REQUIRED** | None in production | **Why Required**: Cryptographic signing of session authentication tokens (HMAC-SHA256). Without this, user identity cannot be validated and token forgery is possible. Must be a 512-bit secure random string (`secrets.token_hex(64)`). |
| `DATABASE_URL` | **REQUIRED** | `sqlite:///./plannededucation.db` | **Why Required**: Specifies the relational database connection. Points to a standalone local file (`sqlite:///...`) for zero-config classroom setups or PostgreSQL (`postgresql+psycopg://...`) for high-concurrency campus deployments. |
| `ENCRYPTION_KEY` | **OPTIONAL** | Derived key | **Why Optional**: Server Fernet encryption key used to encrypt sensitive database columns (e.g. BYOK AI keys, recovery codes, TOTP secrets) at rest. In dev mode it auto-derives; in production it should be set explicitly for cryptographic isolation. |
| `REDIS_URL` | **OPTIONAL** | In-Memory fallback | **Why Optional**: Redis connection string (e.g. `redis://localhost:6379/0`). If omitted, PlannedEducation automatically falls back to local in-memory token-bucket rate limiting (`slowapi`). Recommended when running multiple Uvicorn workers. |
| `SMTP_HOST` / `PORT` | **OPTIONAL** | None (Offline logging) | **Why Optional**: Outgoing school email server for password reset links. If omitted, the platform runs in 100% offline mode: reset links and OTP codes are safely displayed in admin logs and teacher rosters. |
| `BREVO_API_KEY` | **OPTIONAL** | None | **Why Optional**: Free-tier cloud email API (300 free emails/day) for schools without their own SMTP server. Optional alternative to `SMTP_HOST`. |
| `ALLOW_DEV_SEB_BYPASS`| **OPTIONAL** | `false` | **Why Optional**: When `false` (production default), Safe Exam Browser header validation is strictly enforced. When set to `true`, developers can preview SEB exams in standard Chrome/Firefox without installing SEB. |
| `ALLOWED_HOSTS` | **OPTIONAL** | `localhost, 127.0.0.1` | **Why Optional**: Comma-separated list of allowed HTTP Host headers to prevent HTTP Host Header poisoning attacks. Set to your school's server IP or domain name. |
| `CORS_ORIGINS` | **OPTIONAL** | Frontend origin | **Why Optional**: Cross-Origin Resource Sharing whitelist for API access from web clients. |

## 3. External Software Comparison: Behavior With vs. Without External Tools

PlannedEducation is completely self-contained. While it integrates with optional external tools for enhanced lockdown, AI grading, and scalability, it is engineered to function reliably without them.

### 1. Safe Exam Browser (SEB) vs. Standard Web Browser

#### 👩‍🏫 For Teachers & Students
- **With SEB**: The teacher checks "Require Safe Exam Browser" in Exam Settings and gives students a `.seb` configuration file or exam link. When opened, SEB takes over the entire computer screen in kiosk mode. Students cannot open Google, cannot switch to chat applications, cannot use copy-paste, cannot take screenshots, and cannot plug in a second monitor. When the exam is submitted, SEB exits and unlocks the device.
- **Without SEB (Standard Browser)**: Students take the exam in Google Chrome, Mozilla Firefox, Apple Safari, or Microsoft Edge. The platform requests browser Fullscreen mode. If a student leaves the exam tab, minimizes the window, or switches to another program, the platform instantly detects it, logs a "Tab Switch" violation, increments the violation counter, and alerts the teacher in real time.

#### 🛠️ For IT Administrators & Engineers (In-Depth Technical Details)
- **With SEB**:
  - The client transmits two cryptographic HTTP headers on every request:
    * `X-SafeExamBrowser-RequestHash`: Computed as `HMAC-SHA256(request_url, BrowserExamKey)`.
    * `X-SafeExamBrowser-ConfigKeyHash`: Computed as `SHA-256(request_url + ConfigurationKey)`.
  - Backend validation in `src/plannededucation/api/routes_exam.py` (`_verify_seb_request`):
    The server reconstructs the expected hash using the exam's `seb_config_key`. If the header is missing, expired, or invalid, the request is rejected with `403 Forbidden` (`Safe Exam Browser verification failed: configuration mismatch or unauthorized browser`).
  - SEB utilizes low-level OS hooks (`SetWindowsHookEx` on Windows) to trap keyboard shortcuts (`Alt+Tab`, `Ctrl+Alt+Del`, `Win+Tab`, `PrintScreen`) and blocks virtual machine execution (detects VMware, VirtualBox, and Hyper-V guest services).
- **Without SEB**:
  - Client-side DOM event hooks in `TakeExam.tsx`:
    * `document.addEventListener('visibilitychange')`: Detects `document.hidden === true`.
    * `window.addEventListener('blur')`: Detects loss of window focus.
    * HTML5 Fullscreen API (`document.documentElement.requestFullscreen()`): Listens to `fullscreenchange` and logs an incident if fullscreen is exited.
    * Event suppression: `e.preventDefault()` on `contextmenu` and `copy`/`paste` keyboard combinations.

### 2. Optional AI Providers (BYOK) vs. Pure Deterministic / Manual Grading

#### 👩‍🏫 For Teachers & Students
- **With AI (BYOK)**: In **Settings > AI Keys**, a teacher provides an API key for Google Gemini, Anthropic Claude, OpenRouter, OpenAI, or connects a 100% offline local Ollama model. When evaluating exams, the teacher clicks **"AI Correct Selected"**. The AI analyzes long essay answers, suggests a numerical score based on the teacher's rubric, drafts personalized feedback for the student, and assists in drafting exam questions. The teacher reviews all suggestions in the **TeacherCorrectionModal** before anything is finalized.
- **Without AI**: The platform operates 100% deterministically. Multiple-choice, true/false, fill-in-the-blank, and exact mathematical formula questions are evaluated instantly and automatically by the built-in deterministic engine (0ms latency, zero external API calls). Free-text essays are presented to the teacher in the Archive Browser to grade manually with rubric scoring. Zero data ever leaves the local network.

#### 🛠️ For IT Administrators & Engineers (In-Depth Technical Details)
- **With AI**:
  - API keys are stored encrypted in `users.ai_api_key_encrypted` using the server's Fernet encryption key (`cryptography.fernet.Fernet`).
  - **Microsoft Presidio Anonymizer Engine**: Prior to sending student answers to any external AI provider, `src/plannededucation/api/routes_anonymizer.py` invokes Microsoft Presidio (`presidio-analyzer` and `presidio-anonymizer`). The pipeline detects and replaces all PII entities (`PERSON`, `EMAIL_ADDRESS`, `PHONE_NUMBER`, `LOCATION`, `DATE_TIME`) with surrogate tokens (`<STUDENT_NAME_1>`, `<EMAIL_1>`). The association between student IDs and surrogate tokens is stored solely in local server memory.
  - Submissions enter an isolated staging directory on disk (`data/staging_archive/pending_approval/`) before being permanently committed.
- **Without AI**:
  - Direct relational SQL evaluation executed inside an atomic transaction:
    `src/plannededucation/api/routes_exam.py::submit_exam`.
  - Compares submitted option index/value directly against `questions.correct_answer`. For essays, the question state is set to `pending_manual_review`.
  - Zero external HTTP dependencies, zero token costs, and immunity to LLM hallucinations or prompt injection.

### 3. PostgreSQL + Redis vs. Standalone SQLite

#### 👩‍🏫 For Teachers & Administrators
- **SQLite (Mode 1)**: Best for single classrooms or small schools running on one teacher's laptop or classroom desktop. Zero setup: a single file database (`plannededucation.db`). No database servers to install, no passwords to manage. Works straight out of the box with `start_all.bat`.
- **PostgreSQL + Redis (Mode 2 & 3)**: Best for school-wide or university-wide deployments where hundreds or thousands of students take tests simultaneously across multiple classrooms and computer labs.

#### 🛠️ For IT Administrators & Engineers (In-Depth Technical Details)
- **SQLite**:
  - Configured with `connect_args={"check_same_thread": False}`.
  - Employs database-level file locks during write operations. Under concurrent write loads (50+ simultaneous submissions), transactions may queue or encounter `sqlite3.OperationalError: database is locked`.
  - Rate limiting runs via local in-memory dictionaries inside the single Uvicorn process.
- **PostgreSQL + Redis**:
  - Enterprise connection pooling configured in `database.py`: `pool_size=10`, `max_overflow=20`, `pool_pre_ping=True`.
  - Multi-Version Concurrency Control (MVCC) row-level locking handles thousands of simultaneous student submissions across multiple Uvicorn worker processes (`uvicorn --workers 4`).
  - Redis 7 manages distributed token-bucket rate limiting via `slowapi` and real-time WebSocket connection state across clustering nodes.

### 4. SMTP Email vs. Offline School LAN / Logging

#### 👩‍🏫 For Teachers & Students
- **With Email**: Password reset links and verification codes are sent directly to the user's school email inbox.
- **Without Email**: PlannedEducation is 100% functional without email. Teachers can reset student passwords with one click (`⚡ Reset Password`), students can self-reset with their 5 one-time recovery codes, and administrators can reset any password or 2FA device from the Admin Panel.

#### 🛠️ For IT Administrators & Engineers (In-Depth Technical Details)
- **With Email**:
  - `routes_auth.py` connects via `smtplib.SMTP_SSL` (port 465) or `STARTTLS` (port 587) to send RFC 5322 MIME multipart messages. Password reset tokens are signed JWTs with 24-hour expiration (`exp = now + 86400`).
- **Without Email**:
  - The platform operates in offline air-gapped mode. Password reset OTP codes are written to structured JSON logs (`logs/backend.log` with `"security_event": "password_reset_otp"`). Administrators and teachers can directly inspect user recovery states through the UI.

### 5. Docker Containers vs. Native Host Service

#### 👩‍🏫 For School IT
- **Native Host**: Runs directly on Windows (PowerShell/Scheduled Task) or Linux (Systemd). Minimal resource consumption (<250 MB total RAM).
- **Docker Compose**: Containerized execution with automated restart policies and isolated virtual networking.

#### 🛠️ For IT Administrators & Engineers (In-Depth Technical Details)
- **Native Host**:
  - Uses host-level Python virtual environment (`C:/.venv` on Windows, `/opt/plannededucation/.venv` on Linux). Backend binds directly to `127.0.0.1:8000`, frontend served via Vite/Nginx on port 5173 or 80.
- **Docker Compose**:
  - Orchestrates 4 isolated containers on a private bridge network (`plannededucation_net`):
    * `backend`: FastAPI Python 3.12 container running Uvicorn.
    * `frontend`: Static Nginx web server hosting pre-compiled React SPA assets.
    * `postgres`: PostgreSQL 16 Alpine container with persistent volume `postgres_data`.
    * `redis`: Redis 7 Alpine container with persistent volume `redis_data`.

## 4. Classroom Tests vs. Home / Remote Tests

PlannedEducation adapts its user interface, communication channels, and security enforcement depending on whether students are sitting together in a physical classroom or taking exams remotely from home.

### Comparison Table: Classroom vs. Home Testing

| Feature / Dimension | 🏫 Physical Classroom Test | 🏠 Home / Remote Exam |
|:---|:---|:---|
| **Delivery Mode Setting** | `delivery_mode: "classroom"` | `delivery_mode: "different_location"` |
| **Network Infrastructure** | School Local LAN (`http://192.168.1.X:8000`) | School VPN, Reverse Proxy (HTTPS), or Cloudflare Tunnel |
| **Internet Dependency** | **Zero**. Works on offline air-gapped router. | Requires student home internet connection for start & submit. |
| **Student Questions / Help** | Students raise their physical hand in the room. | **Digital Hand Raise** enabled; sends real-time alert to teacher dashboard. |
| **Password Emergency Reset**| Teacher clicks **"⚡ Reset Pwd for Test"** in room roster. | Student uses 1 of 5 recovery codes, or parent requests link. |
| **Safe Exam Browser (SEB)** | Strongly recommended; enforces strict local lockdown. | Optional or required via pre-shared `.seb` config key. |
| **Proctoring Telemetry** | Teacher physically monitors desks; basic tab switch log. | Fullscreen lock, tab switch tracking, optional local webcam/audio analysis. |
| **Network Interruption Risk**| Resilient to Wi-Fi drops via local IndexedDB buffer. | Fully cached locally; auto-submits locally when timer expires. |

---

#### 👩‍🏫 For Teachers & Students: Practical Workflow Differences

1. **In the Classroom**:
   - The teacher starts the exam and writes the **Exam Code** on the blackboard.
   - Students join from school computers or tablets connected to the school Wi-Fi or LAN.
   - If a student forgot their password, the teacher clicks **"⚡ Reset Pwd for Test"** next to their name on the teacher dashboard. The student immediately types a new password on `/login` and starts the test without needing email.
   - If a student has a question during the test, they simply raise their physical hand. (The digital hand raise button is automatically hidden to avoid distraction).
   - If the school Wi-Fi router restarts or drops during the exam, **the exam does not stop**. The student continues answering questions without interruption.

2. **At Home / Remote**:

   - Because the teacher is not physically in the room, the **Digital Hand Raise** (`🙋 Raise Hand`) button is active. Clicking it sends an instant notification to the teacher's monitor, opening a secure, private chat channel.

   - Optional webcam and audio proctoring can be toggled by the teacher to ensure fair testing conditions.

#### 🛠️ For IT Administrators & Engineers: Technical Architecture

1. **Classroom LAN Routing & Air-Gapped Mode**:
   - In `TakeExam.tsx`, when `examPackage.settings.delivery_mode === 'classroom'`, the UI component sets `allow_digital_hand_raise = false`, suppressing WebSocket chat channels.
   - The backend runs on the teacher's desktop or school server. Port `8000` is opened in Windows Firewall (`New-NetFirewallRule -DisplayName "PlannedEducation Server" -Direction Inbound -LocalPort 8000 -Protocol TCP -Action Allow`).
   - `.env` configuration for LAN:
     ```env
     ALLOWED_HOSTS=localhost,127.0.0.1,192.168.1.*,exam.school.local
     CORS_ORIGINS=http://localhost:5173,http://192.168.1.*:5173
     ```
   - No external DNS or public internet routing is required.

2. **Remote / Home WAN Architecture**:
   - Remote access requires Transport Layer Security (TLS/HTTPS) to encrypt exam tokens in transit.
   - The frontend is served behind an Nginx reverse proxy or Cloudflare Tunnel:
     ```nginx
     location /api/ {
         proxy_pass http://127.0.0.1:8000/;
         proxy_set_header Host $host;
         proxy_set_header X-Real-IP $remote_addr;
         proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
         proxy_set_header X-Forwarded-Proto $scheme;
     }
     location /ws/ {
         proxy_pass http://127.0.0.1:8000/ws/;
         proxy_http_version 1.1;
         proxy_set_header Upgrade $http_upgrade;
         proxy_set_header Connection "upgrade";
     }
     ```
   - Rate limiting is strictly enforced: `500 requests/minute` per IP address to defend against credential stuffing and DoS attacks.

## 5. Offline Exam Engine & Three-Way Cryptographic Sealing

PlannedEducation incorporates an advanced, client-side offline execution engine located in [`web/apps/portal/src/services/offlineExam.ts`](file:///c:/dev/PlannedEducation/web/apps/portal/src/services/offlineExam.ts).

### The Three-Way Immutable Storage Model
To guarantee that neither student tampering, network failure, nor server synchronization bugs can compromise test scores, PlannedEducation implements a **three-way immutable storage architecture**:

```
+--------------------------------------------------------------------------+
|                       THREE-WAY IMMUTABLE STORAGE                        |
+--------------------------------------------------------------------------+
|  1. Student Local Storage     2. Teacher LAN Device     3. Central Server |
|     (Browser IndexedDB)          (Teacher Monitor)         (Postgres/SQL) |
|     * Encrypted AES-GCM          * Backup Sync Copy        * Audit Log    |
|     * Local Countdown Timer      * Real-Time Progress      * Sealed State |
|     * SHA-256 Content Hash       * Integrity Check         * Permanent    |
+--------------------------------------------------------------------------+
         \                              |                              /
          \                             |                             /
           +----------------------------+----------------------------+
                                        |
                            Cross-Verification Hash
                           (All 3 Copies Must Match)
```

1. **Student Local Copy**: Cryptographically sealed in browser **IndexedDB** (`plannededucation-offline-exam`), encrypted with AES-GCM, and signed with a SHA-256 hash.
2. **Teacher Device Copy**: Transmitted over local LAN or cached in the teacher's browser memory during exam monitoring.
3. **Server Copy**: Persisted in the primary database with audit log timestamps.

All three copies must produce identical SHA-256 content hashes, eliminating the possibility of grade tampering by any party.

---

#### 👩‍🏫 For Teachers & Students: What Happens If Wi-Fi Fails During a Test?

1. **Before the Exam Starts**: When a student enters the exam code, the complete exam package (questions, choices, rubrics, and settings) is downloaded and cached securely into the student's browser.
2. **During the Exam**:
   - The countdown timer runs **locally inside the student's device**. It does not depend on the server.
   - Every time the student clicks an answer or types an essay response, the answer is saved instantly into local storage (IndexedDB).
   - If the school or home Wi-Fi drops completely, **no error screen appears**. A subtle indicator notes that the device is temporarily offline, but the student continues answering questions as normal.
3. **When Time Runs Out**:
   - When the countdown timer reaches `00:00`, the exam **auto-submits locally**. The student cannot add more answers.
   - The answers are cryptographically locked and sealed into an immutable archive on the student's device.
4. **When Connection Returns**:
   - The sealed archive synchronizes automatically with the server in the background.
   - If the device remains completely offline even after the test, the teacher can export the student's sealed submission package via USB or local network and import it directly into the Teacher Dashboard with 100% integrity verification.

---

#### 🛠️ For IT Administrators & Engineers: Cryptographic & Storage Architecture

1. **IndexedDB Schema (`plannededucation-offline-exam` version 2)**:
   - `offlineExams`: Stores active `OfflineExamState` (`examId`, `studentId`, `answers`, `answerTimestamps`, `timeRemainingMs`, `timerState`, `sebViolations`).
   - `examPackages`: Stores cached `ExamPackage` metadata.
   - `sealedSubmissions`: Append-only immutable store containing `SealedExamSubmission`.
   - `syncQueue`: Queue tracking synchronization status to teacher device and central server.

2. **Cryptographic Sealing Pipeline**:
   - **Algorithm**: `AES-GCM` with a 256-bit key derived via PBKDF2 (SHA-256, 100,000 iterations).
   - **Initialization Vector (IV)**: 12-byte (96-bit) cryptographically random nonce generated via `crypto.getRandomValues()`.
   - **Integrity Digest**: Prior to encryption, canonical JSON representation of answers is hashed with `SHA-256`. The resulting `contentHash` is stored in the header.
   - **Verification**: On receipt, the server computes `SHA-256(decrypted_payload)` and compares it against `contentHash`. If tampering has occurred, the submission is flagged as invalid.

## Account & Security

### How do I reset my password?
PlannedEducation offers 3 easy ways to recover access:
1. **Self-Reset with Recovery Codes (Fastest & Independent)**: Upon registration, all users (students, teachers, administrators) receive **5 one-time recovery codes**. On the login screen, click 'Forgot Password?', enter your email and any one of your recovery codes, and set a new password instantly without needing assistance or waiting for emails.
2. **Pre-Exam Quick Reset by Teacher (Classroom Emergency)**: If a student forgets their password right before a test, the teacher can click the yellow **"⚡ Reset Pwd for Test"** button next to the student's name in the classroom roster. The student simply goes to `/login`, enters their school email, and is prompted to type a new password right in the login form to start the exam immediately.
3. **Supervisor Request or Admin Reset**: Users who run out of recovery codes can request a reset from their assigned teacher or parent, or a school administrator can reset their password directly from the Admin Panel.

### Can administrators reset passwords directly without email?
Yes! In school and classroom deployments without an active email server, administrators can reset any user's password directly from the **Admin Panel > Users** tab. Simply click the **🔑 Reset Password** button next to the user. You can type a custom password or let the system auto-generate a temporary password. You can also check 'Reset 2FA & Passkeys' to instantly recover an account if the user lost their authenticator device.

### How do database backups work?
PlannedEducation includes a native automated backup service:
- **Automated Midnight Backups**: Every day at **00:00 UTC**, an atomic snapshot of the database is automatically created and stored in the `backups/` directory.
- **Automated Retention**: Archives older than 30 days are automatically pruned to conserve disk space.
- **Instant Admin Backups**: Administrators can click the **💾 Create Backup Now** button in the Admin Panel anytime to create an immediate on-demand snapshot and download it directly.
- **Engines Supported**: Full support for both SQLite (using atomic non-locking online backups) and PostgreSQL (using compressed `pg_dump`).

### How do I configure email for password resets?
Email is 100% optional. If unconfigured, PlannedEducation operates in self-contained offline mode and logs OTP codes safely. If you wish to enable outgoing email, configure either **Brevo (Sendinblue)** with `BREVO_API_KEY` (free tier: 300 emails/day) or your **School / Campus SMTP Server** (`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`) in `.env`.

### How do I enable two-factor authentication?
Go to Settings > Security, click 'Enable 2FA', scan the QR code with your authenticator app, and enter the verification code to complete setup. Save your 5 recovery codes in case you lose your phone. If you ever lose your phone and recovery codes, a school administrator can reset your 2FA from the Admin Panel.

### What are Passkeys and how do I use them?
Passkeys are a passwordless authentication method using biometrics or device PIN. You can set them up in Settings > Passkeys by registering your device's biometric authentication. Passkeys sync across devices via iCloud Keychain or Google Password Manager.

### How do I register a Passkey?
Go to Settings > Passkeys, click 'Register Passkey', and use your device's biometric (fingerprint, face ID) or PIN to create the passkey. It will sync across your devices automatically.

**Limitations**:
- Cost estimates are based on static pricing tables that may be outdated
- Only tracks token counts from API responses (when available)
- Does NOT account for: cached tokens, batch discounts, enterprise pricing, regional pricing, model version changes, provider-specific pricing tiers
- Should NOT be relied upon for billing, budgeting, or financial decisions

**Teacher Responsibility**: Teachers **MUST** monitor their own AI provider dashboards for actual costs.

**Configuration**: 
- `MAX_DAILY_COST_USD` env var (default 5.0)

**Recommendation**: Treat as a rough guardrail only; disable if not needed.

`curl -fsSL https://raw.githubusercontent.com/ezixen/PlannedEducation/main/install.sh | bash`
Or clone the repository and run `./install.sh`. The installer supports Ubuntu 22.04/24.04, Debian 12, and CentOS/RHEL with Native Systemd service setup or Docker Compose. See [Linux Installation Guide](../admin/INSTALL_LINUX.md).

### Can I run PlannedEducation without Docker (Native Mode)?
Yes! Both `install.ps1` and `install.sh` support **Native Mode**. It runs directly on the host using Python 3.12+ and can use SQLite (zero-configuration standalone database) or local PostgreSQL and Redis. This reduces memory usage and eliminates Docker overhead for small school servers.

### How do I use the Cross-Platform Deployment Wizard?
Run `python scripts/deploy/deploy_wizard.py` (or `python3 scripts/deploy/deploy_wizard.py`). It works on Windows, Linux, and macOS, automatically verifies dependencies, generates secure encryption secrets (JWT and Fernet keys), and guides you through setting up either Native or Docker deployment. See [Master Deployment Guide](../admin/DEPLOYMENT_GUIDE.md).

### How do teachers and students connect over the local school network (Wi-Fi/LAN)?
1. Find the server's local IPv4 address (e.g., `192.168.1.150`).
2. Open port 8000 (or 80) in the host firewall (`New-NetFirewallRule` on Windows or `sudo ufw allow 8000/tcp` on Linux).
3. In `.env`, add the server IP to `ALLOWED_HOSTS` and `CORS_ORIGINS`.
4. Teacher and student devices simply navigate to `http://<SERVER_IP>:8000` in any web browser or Safe Exam Browser (SEB).

## 2. Classroom & Student Management

### Creating Classes

2. Click **Create Class**, enter the class name, grade level, and subject.
3. Share the class join code with your students, or add student accounts directly.

### Pre-Exam Emergency Password Reset ("⚡ Reset Pwd for Test")
Right before a scheduled exam, students frequently forget their passwords and panic under time pressure. PlannedEducation eliminates exam delays with a single-click teacher unlock:
1. In **Teacher Dashboard → Real-Time Student Monitoring** or **Classes → Manage Students**, locate the locked-out student in your roster.
2. Click the yellow **"⚡ Reset Pwd for Test"** button next to their name.
3. Confirm the quick reset dialog.
4. **Student Next Step**: Instruct the student to open the login page (`/login`) and enter their school email. The system immediately detects the active teacher unlock (`TEACHER_RESET_ACTIVE`), highlights the form in green, and prompts the student to type a new password right in the login card.
5. Upon typing their password and clicking **"Set Password and Sign In"**, the student is immediately authenticated and admitted directly into the test session.

## 3. Exam Authoring & Dynamic Math Variables

### Question Types Supported
- **Multiple Choice (Single & Multi-Select)**: Auto-graded instantly.
- **Short Answer**: Keyword and regex matching.
- **Essay & Long Form**: Detailed rubrics with AI-assisted drafting and teacher review.
- **Math & Chemistry**: LaTeX notation with dynamic numerical variables.

### Dynamic Math Variables & Seeded Formulas
To prevent students sitting next to each other from copying answers:
- Embed variables inside brackets: e.g. `Solve for x: {a}x + {b} = {c}`
- Configure variable ranges and step sizes (e.g. `a: 2..10`, `b: 1..20`).
- Specify formulas for automated evaluation (e.g. `x = (c - b) / a`).
- Each student receives a deterministically seeded set of numbers so that exam questions remain identical in concept while values differ per workstation.

### Curriculum Modules & Question Banks
- Group related questions into reusable **Modules** (e.g. *Unit 3: Quadratic Equations* or *Cell Biology*).
- Tag questions by difficulty, IEP accommodation, and curriculum standard.
- Import/export test packages using the standardized `.pepkg` format to share curriculum with colleagues across your school or district.

## 4. Secure Exam Browser (SEB) & Lockdown Mode

PlannedEducation natively supports **Safe Exam Browser (SEB)** to guarantee a secure, locked-down testing environment:
1. When publishing an exam, toggle **Require Safe Exam Browser**.
2. Download the pre-configured `.seb` file or distribute the direct SEB launch link to students.
3. During the exam:
   - OS shortcuts (Alt+Tab, Windows Key, Ctrl+Alt+Del) are disabled.
   - Screen capture, virtual machines, and external monitors are restricted.
   - Network requests are strictly pinned to the PlannedEducation exam server.
4. **Emergency Exit**: If a workstation encounters a hardware fault or restarts, the student re-authenticates with SEB or requests teacher intervention without losing already saved answers.

---

## 5. Archive Browser & AI-Assisted Grading Workflow

PlannedEducation provides a comprehensive **Archive Browser & AI Grading Pipeline** built directly into the Teacher Dashboard:

### 1. The Archive Browser
- View all completed class exam submissions and offline uploaded test packages in one centralized table.
- Filter by Exam, Year, Month, or Status:
  - `ungraded` (Gray: *Submitted / Needs Grading*)
  - `pending_approval` (Amber: *AI Corrected — Staged in Temp Folder, Pending Teacher Review*)
  - `graded` (Green: *Graded & Sealed in Archive*)
- Multi-select checkboxes allow batch operations across multiple student submissions.

### 2. Privacy-Preserving AI Grading (Zero PII Exposure)
- Select one or more tests and click **"🤖 AI Correct Selected"**.
- **Microsoft Presidio PII Scrubber**: Automatically sanitizes all student personal identifying information (names, email addresses, phone numbers, locations, dates, IDs) from responses and prompts before external evaluation.
- The AI evaluates each answer against your rubric or correct answer, provides constructive feedback, explains mistakes, suggests step-by-step solutions, and proposes scores.
- **Local Fallback**: If no external AI key is configured, PlannedEducation uses a deterministic local rubric matcher so the system works 100% offline.

### 3. Temporary Staging in Temp Folder (`pending_approval`)
- Returned AI suggestions and grades are placed in a secure temporary staging folder on disk: `data/staging_archive/{teacher_id}/{submission_id}.json`.
- The submission status moves to **"AI Corrected (Pending Approval)"**.
- Student identities remain safely mapped in the local database for teacher-only view, while remaining completely hidden from external models.

### 4. Teacher Review & Correction Modal
- Click **"✏️ Review & Correct"** to open the interactive **TeacherCorrectionModal**.
- Side-by-side comparison:
  - **Left**: Original student submission and rubric points.
  - **Right**: AI evaluation, confidence indicator, and step-by-step suggestions.
  - **Bottom/Editor**: Quick feedback chips ("Excellent step-by-step work!", "Correct method, minor arithmetic error", etc.), score adjustments, and solution overrides.
- Teachers can approve questions individually or click **"✓ Approve All & Save Corrected Exam"**.

### 5. Sealing & Encrypted Archiving
- When approved, final scores and feedback are written to the database.
- The test is compressed using **zstandard (zstd)** and encrypted using **AES-GCM**.
- SHA-256 integrity hashes are computed and recorded in `ArchivedSubmission`.
- The temporary staging file is safely cleaned up, and the test is marked **"Graded & Sealed"** (`graded`).
- Sealed archives can be downloaded directly as encrypted `.zst.enc` files.

### 6. Reviewable & Re-correctable Any Time
- Archived tests are never locked permanently away from educators.
- Teachers can click **"🔄 Re-open & Re-correct"** at any time to return a graded test to staging, adjust points or comments if a mistake was made, and re-seal it into the archive.

### 7. Offline Test Package Uploads
- Teachers can upload offline test submissions or student responses (`.json`, `.txt`, `.zip`) directly via the **"📤 Upload Test Paper"** button in the Archive Browser.
- Uploaded tests are registered immediately, ready for AI or manual grading.

## 2. Configuration Matrix: Required vs. Optional Settings

PlannedEducation enforces strict separation between required security settings and optional enhancement modules:

| Environment Variable | Status | Default / Fallback | Purpose & Why It Is Required or Optional |
|:---|:---:|:---|:---|
| `JWT_SECRET_KEY` | **REQUIRED** | None in production | **Why Required**: Cryptographic signing of session authentication tokens (HMAC-SHA256). Without this, user identity cannot be validated and token forgery is possible. Must be a 512-bit secure random string (`secrets.token_hex(64)`). |
| `DATABASE_URL` | **REQUIRED** | `sqlite:///./plannededucation.db` | **Why Required**: Specifies the relational database connection. Points to a standalone local file (`sqlite:///...`) for zero-config classroom setups or PostgreSQL (`postgresql+psycopg://...`) for high-concurrency campus deployments. |
| `ENCRYPTION_KEY` | **OPTIONAL** | Derived key | **Why Optional**: Server Fernet encryption key used to encrypt sensitive database columns (e.g. BYOK AI keys, recovery codes, TOTP secrets) at rest. In dev mode it auto-derives; in production it should be set explicitly for cryptographic isolation. |
| `REDIS_URL` | **OPTIONAL** | In-Memory fallback | **Why Optional**: Redis connection string (e.g. `redis://localhost:6379/0`). If omitted, PlannedEducation automatically falls back to local in-memory token-bucket rate limiting (`slowapi`). Recommended when running multiple Uvicorn workers. |
| `SMTP_HOST` / `PORT` | **OPTIONAL** | None (Offline logging) | **Why Optional**: Outgoing school email server for password reset links. If omitted, the platform runs in 100% offline mode: reset links and OTP codes are safely displayed in admin logs and teacher rosters. |
| `BREVO_API_KEY` | **OPTIONAL** | None | **Why Optional**: Free-tier cloud email API (300 free emails/day) for schools without their own SMTP server. Optional alternative to `SMTP_HOST`. |
| `ALLOW_DEV_SEB_BYPASS`| **OPTIONAL** | `false` | **Why Optional**: When `false` (production default), Safe Exam Browser header validation is strictly enforced. When set to `true`, developers can preview SEB exams in standard Chrome/Firefox without installing SEB. |
| `ALLOWED_HOSTS` | **OPTIONAL** | `localhost, 127.0.0.1` | **Why Optional**: Comma-separated list of allowed HTTP Host headers to prevent HTTP Host Header poisoning attacks. Set to your school's server IP or domain name. |
| `CORS_ORIGINS` | **OPTIONAL** | Frontend origin | **Why Optional**: Cross-Origin Resource Sharing whitelist for API access from web clients. |

## 3. External Software Integration: With vs. Without External Tools

PlannedEducation is completely self-contained. While it integrates with optional external tools for enhanced lockdown, AI grading, and scalability, it is engineered to function reliably without them.

### 1. Safe Exam Browser (SEB) vs. Standard Web Browser
- **👩‍🏫 Teachers/Students**:
  - *With SEB*: Kiosk lockdown takes over the computer screen. Prevents opening other windows, using chat, taking screenshots, or connecting second monitors.
  - *Without SEB*: Students use regular Chrome, Firefox, Safari, or Edge. Browser fullscreen is requested. If a student switches tabs or minimizes the window, the platform logs a violation and alerts the teacher.
- **🛠️ IT Administrators**:
  - *With SEB*: Enforces `X-SafeExamBrowser-RequestHash` (HMAC-SHA256) and `X-SafeExamBrowser-ConfigKeyHash`. Server validates against exam `seb_config_key` in `routes_exam.py::_verify_seb_request`. OS hooks block `Alt+Tab` and virtual machines.
  - *Without SEB*: Relies on DOM events (`visibilitychange`, `blur`, Fullscreen API). Event handlers log violations to database audit trail.

### 2. Optional AI Providers (BYOK) vs. Pure Deterministic / Manual Grading
- **👩‍🏫 Teachers/Students**:
  - *With AI (BYOK)*: In Settings > AI Keys, configure Google Gemini, Anthropic Claude, OpenRouter, or local Ollama. Suggests essay scores and rubric feedback. Teacher reviews in TeacherCorrectionModal before approving.
  - *Without AI*: Deterministic evaluation grades multiple-choice, true/false, and math formulas instantly (0ms latency, 0 external calls). Free-text essays are manually evaluated by the teacher. 100% offline, zero data leaves the school network.
- **🛠️ IT Administrators**:
  - *With AI*: Keys encrypted at rest via Fernet. **Microsoft Presidio** scrubs PII (`PERSON`, `EMAIL`, `PHONE`, `LOCATION`) into surrogate tokens (`<STUDENT_NAME_1>`) before transmission. Staged in `data/staging_archive/pending_approval/`.
  - *Without AI*: Direct SQL transactions in `routes_exam.py::submit_exam`. Zero third-party network exposure, zero token cost.

### 3. PostgreSQL + Redis vs. Standalone SQLite
- **👩‍🏫 Teachers/Administrators**:
  - *SQLite (Mode 1)*: Best for single classrooms or laptop servers. Zero setup, single file database (`plannededucation.db`).
  - *PostgreSQL + Redis (Mode 2 & 3)*: School-wide or university server for hundreds/thousands of concurrent students.
- **🛠️ IT Administrators**:
  - *SQLite*: Database file locks during writes; suitable for single-process Uvicorn. In-memory slowapi rate limiting.
  - *PostgreSQL + Redis*: Connection pooling (`pool_size=10`, `max_overflow=20`), MVCC row-level locking for concurrent writes across multiple Uvicorn workers (`uvicorn --workers 4`), distributed Redis token-bucket limiter.

## 5. Offline Exam Execution & Three-Way Cryptographic Sealing

PlannedEducation implements an advanced client-side offline execution engine in [`web/apps/portal/src/services/offlineExam.ts`](file:///c:/dev/PlannedEducation/web/apps/portal/src/services/offlineExam.ts).

### Three-Way Immutable Storage Architecture
1. **Student Local Storage**: Browser IndexedDB (`plannededucation-offline-exam`), encrypted with AES-GCM (256-bit key derived via PBKDF2), signed with SHA-256 hash.
2. **Teacher Device / LAN**: Real-time progress copy held on the teacher's monitor.
3. **Central Server**: Final database record with audit trail.

### What Happens If Wi-Fi Drops Midway Through a Test?
1. The student's device holds the downloaded exam package in local storage.
2. The countdown timer runs **locally inside the device** (not on the server).
3. Every keystroke and click is saved instantly into IndexedDB.
4. If Wi-Fi drops, **no interruption occurs**. The student continues answering questions as normal.
5. When the countdown reaches `00:00`, the exam auto-submits and seals locally.
6. When connection is restored, the sealed package synchronizes automatically to the teacher dashboard and server with SHA-256 verification.

## Backup Strategy

### 0. Native Midnight Auto-Backup Scheduler (Built-In)
PlannedEducation includes a native background backup scheduler (`backup_service.py`):
- **Automated Schedule:** Runs daily at **00:00 UTC** while the server is active.
- **Automated Retention:** Automatically prunes backup archives older than **30 days**.
- **Admin Dashboard Control:** Administrators can create an instant snapshot anytime via **Admin Dashboard → 💾 Database Backups** and download archives directly from the browser.
- **Engine Support:**
  - SQLite: Uses atomic `sqlite3.connect().backup()` to prevent table locks.
  - PostgreSQL: Uses `pg_dump` with gzip compression.

### 1. PostgreSQL Database

#### External / Scripted Backups
```bash
# Script: scripts/backup/backup_restore.sh (PostgreSQL section)
# Schedule: Daily via cron or systemd timer
# Retention: 30 daily + 12 monthly + 7 yearly

pg_dump \
  --host=localhost \
  --port=5432 \
  --username=postgres \
  --dbname=plannededucation \
  --format=custom \
  --compress=9 \
  --no-owner \
  --no-privileges \
  --file=/backups/plannededucation_$(date +%Y%m%d_%H%M%S).dump
```

#### Encryption
```bash
# Encrypt with age (modern, simple encryption)
age -r age1...public_key... -o backup.dump.age backup.dump
```

#### Storage Locations (Free Tier)
- **Primary**: Local filesystem (mounted volume)
- **Secondary**: GitHub Actions artifacts (90-day retention)
- **Tertiary**: Cloudflare R2 / AWS S3 free tier (if configured)

### 2. Redis Cache

## Restore Procedures

### 1. PostgreSQL Restore (Full)

```bash
# 1. Stop application
docker compose stop backend portal

# 2. Drop & recreate database
psql -U postgres -c "DROP DATABASE IF EXISTS plannededucation;"
psql -U postgres -c "CREATE DATABASE plannededucation;"

# 3. Restore from latest backup
pg_restore \
  --host=localhost \
  --port=5432 \
  --username=postgres \
  --dbname=plannededucation \
  --clean \
  --if-exists \
  --no-owner \
  --no-privileges \
  /backups/plannededucation_latest.dump

# 4. Run migrations (if any)
cd /app && alembic upgrade head

# 5. Restart application
docker compose start backend portal
```

```bash
# If WAL archiving enabled:

```

## Automated Restore Drills

### Monthly Drill Schedule
- **When**: First Saturday of each month, 03:00 UTC
- **Environment**: Staging (separate from production)
- **Scope**: Full PostgreSQL restore + application deploy
- **Validation**: Automated smoke tests

### Drill Script
```bash
#!/bin/bash
# scripts/backup_restore_drill.sh

set -euo pipefail

STAGING_DB="plannededucation_staging"
BACKUP_FILE=$(ls -t /backups/plannededucation_*.dump | head -1)

echo "=== Starting Monthly Restore Drill ==="
echo "Backup file: $BACKUP_FILE"
echo "Target DB: $STAGING_DB"

# 1. Create staging database
psql -U postgres -c "DROP DATABASE IF EXISTS $STAGING_DB;"
psql -U postgres -c "CREATE DATABASE $STAGING_DB;"

# 2. Restore
pg_restore -U postgres -d $STAGING_DB --clean --if-exists "$BACKUP_FILE"

# 3. Run migrations
cd /app && DATABASE_URL="postgresql://postgres@localhost:5432/$STAGING_DB" alembic upgrade head

# 4. Run smoke tests
cd /app && pytest tests/test_auth.py tests/test_exams.py -x -q

# 5. Cleanup
psql -U postgres -c "DROP DATABASE $STAGING_DB;"

echo "=== Restore Drill Completed Successfully ==="
```

### Drill Success Criteria
- [ ] Restore completes without errors
- [ ] All migrations apply cleanly
- [ ] Smoke tests pass (auth, exams, basic API)
- [ ] Data integrity checks pass (row counts, foreign keys)
- [ ] Drill completes within RTO (4 hours)

## Backup Validation

### Automated Checks (Post-Backup)
```bash
# 1. Verify dump file exists and is non-zero
test -s /backups/plannededucation_latest.dump

# 2. Verify pg_restore can read header
pg_restore --list /backups/plannededucation_latest.dump > /dev/null

# 3. Verify encryption (if using age)
age --decrypt -i /keys/age.key -o /tmp/test.dump /backups/plannededucation_latest.dump.age

```

### Alerting
- **Backup failure**: Alert if backup job exits non-zero
- **Backup size anomaly**: Alert if backup size changes > 50% from 7-day average
- **Backup age**: Alert if latest backup > 36 hours old

## Disaster Scenarios & Response

| Scenario | Detection | Response | Recovery |
|---|---|---|---|
| **Database corruption** | App errors, pg_dump fails | Failover to replica (if exists) or restore from backup | Full DB restore + migration |
| **Accidental data deletion** | Audit log, missing data | Point-in-time recovery or restore specific tables | PITR or table-level restore |
| **Ransomware/encryption** | File system alerts, inaccessible files | Isolate, restore from offline/immutable backup | Full restore from clean backup |
| **Region outage** | Health checks fail | Failover to secondary region (if multi-region) | DNS failover, DB replica promotion |
| **Secrets compromise** | Unusual access patterns | Rotate all secrets, revoke tokens | Re-deploy with new secrets |

## Internationalization (i18n) & Translation System

## Overview

This document describes the internationalization (i18n) system for PlannedEducation, including how translations work, how to add new languages, and how to contribute translations.

## System Overview

PlannedEducation uses a **numbered key system** for translations with the format `page.element` (e.g., `login.1`, `dashboard.3`, `settings.12.3`). This allows:

- **Visual identification** of translatable elements on the UI
- **Easy synchronization** between English source and translations
- **Context-aware translation** with detailed context documentation
- **Visual toggle** for translation numbers in the UI

## File Structure

```
web/apps/portal/src/locales/
├── en/
│   ├── messages.json      # Source English translations (436 keys)
│   └── CONTEXT.md         # Detailed context for each key
├── hu/
│   └── messages.json      # Hungarian translations (436 keys)
├── es/
│   └── messages.json      # Spanish translations (to be created)
├── de/
│   └── messages.json      # German translations (to be created)
├── fr/
│   └── messages.json      # French translations (to be created)
├── ja/
│   └── messages.json      # Japanese translations (to be created)
├── zh/
│   └── messages.json      # Chinese translations (to be created)
└── CONTEXT.md             # Master context documentation
```

## Key Format

Keys follow the format: `page.element` where:
- `page` = page/section identifier (e.g., `login`, `dashboard`, `settings`, `exam_editor`)
- `element` = sequential number within that page (e.g., `1`, `2`, `3`, `10.1`, `10.2`)

Examples:
- `login.1` = "Planned Education" (page title)
- `login.3` = "Email address" (label)
- `settings.12.3` = "API Key" (sub-item under AI Key Management)

## Translation Rules

### 1. Keep in English (Do Not Translate)
- **Brand names**: "Planned Education", "Google", "GitHub", "OpenAI", "Ollama"
- **Technical terms**: API, URL, PDF, OAuth, JWT, JSON, YAML, HTML, CSS, JS, SQL, UUID, UUID, HTTP, HTTPS, REST, GraphQL, WebSocket, WebRTC, SEB, GDPR, OCR, STT, TTS, AI, LLM, RAG, RTP, RTCP, ICE, STUN, TURN, SDP, DTLS, SRTP, SRTCP, RTCP, RTP, RTCP
- **Proper nouns**: Planned Education, Google, GitHub, OpenAI, Ollama, OpenRouter, Anthropic, Claude, Gemini, ChatGPT, iCloud, Keychain, Windows Hello, Touch ID, Face ID, PIN
- **Units**: KB, MB, GB, TB, Hz, MHz, GHz, ms, s, min, h, d, px, em, rem, %, °C, °F
- **Format strings**: `{variable}`, `%s`, `%d`, `%f`, `%.2f`, `{0}`, `{1}`, `{count}`, `{name}`

### 2. Translate Naturally
- Use formal/informal appropriately for the target language
- Maintain consistent terminology across the application
- Consider cultural context and regional variations

### 3. Special Cases
- **Brand names**: Keep "Planned Education" in English
- **Technical acronyms**: Keep SEO, API, URL, PDF, OAuth, JWT, etc. in English
- **Units**: Keep KB, MB, GB, ms, s, min, h, etc. as-is
- **Placeholders**: Keep `{variable}`, `%s`, `%d` as-is

### English Source (`en/messages.json`)

## 14. Archive Browser & AI Grading Pipeline

### Microsoft Presidio PII Anonymization
When a teacher triggers AI grading assistance on written answers:
1. The backend invokes Microsoft Presidio.
2. All student names, dates of birth, email addresses, phone numbers, and location references are replaced with cryptographic surrogates (`<STUDENT_NAME_1>`, `<EMAIL_1>`).
3. Only scrubbed answer text is evaluated by the AI model.
4. The local database associates the feedback with the real student identity only within the teacher's private dashboard.

### Staging State & Teacher Correction Modal
1. Evaluated submissions enter a temporary staging directory on disk (`data/staging_archive/pending_approval/`).
2. Teachers open the **TeacherCorrectionModal** in the Archive Browser.
3. Teachers can inspect AI scores and explanations, override points, adjust feedback, and click **Approve & Seal**.
4. The finalized test is compressed with **zstd**, encrypted with **AES-GCM**, and stored in the permanent archive with a SHA-256 integrity hash.
5. Graded archives can be reopened and re-corrected at any time using the **🔄 Re-correct** button without losing audit trails.

## 15. Safe Exam Browser (SEB) & Lockdown Proctoring

### SEB Key Verification
PlannedEducation natively integrates with Safe Exam Browser (open-source lockdown browser for Windows, macOS, and iOS):
- **Browser Exam Key (BEK)**: Ensures the request comes from an official SEB client binary.
- **Configuration Key (CK)**: Validates that the client is running the exact `.seb` configuration file distributed by the teacher.
- **Lockdown Protections**: Disables clipboard cut/copy/paste, prevents multi-monitor setups, blocks virtual machines, and disables Wi-Fi/Bluetooth toggling during exams.

### Privacy-Preserving Proctoring
When enabled in exam settings:
- Detects window and tab switches.
- Monitors ambient audio spikes.
- Optional webcam gaze tracking (all analysis runs locally via browser WebAssembly/TensorFlow.js; video streams are never transmitted or stored remotely).

## 22. Testing Cache & Process Hygiene Guardrails

### Source-Aware Pytest Cache Helper
PlannedEducation uses a custom test cache manager to eliminate redundant test executions:
- **Wrapper**: `scripts/testing/update_test_cache.py`
- **Standard Invocations**:
  ```powershell
  # Run full test suite with change tracking:
  C:/.venv/Scripts/python.exe scripts/testing/update_test_cache.py --skip-if-clean --suite-name "backend-all" -- C:/.venv/Scripts/python.exe -m pytest tests/ -q

  # Run focused tests with change tracking:
  C:/.venv/Scripts/python.exe scripts/testing/update_test_cache.py --skip-if-clean --suite-name "curriculum-and-ai" -- C:/.venv/Scripts/python.exe -m pytest tests/test_ai_exam_creation_api.py tests/test_germany_curriculum_modules.py tests/test_mit_curriculum_modules.py -q
  ```
- Computes SHA-256 signatures of source files and dependencies. Unmodified test suites are automatically skipped (`Skipped pytest: suite is clean`).
- Real-time debug logs are continuously appended to `artifacts/test_run.log`.

### Orphaned Process Prevention
To prevent background processes from leaking memory or locking SQLite files, run the cleanup command before and after test runs:
```powershell
Get-Process -Name "node", "python", "uvicorn" -ErrorAction SilentlyContinue | Where-Object {$_.Id -ne $PID} | Stop-Process -Force
```
